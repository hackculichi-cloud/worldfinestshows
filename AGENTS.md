# Project instructions

- Communicate with the project owner in Spanish. The public website remains in English, matching the reference audience.
- Deliver changes on a feature branch with a pull request for the owner to review and accept. Do not merge your own PR or push application changes directly to main.
- Include a preview with every visual delivery. Prefer a verified interactive preview URL; when hosting is unavailable, provide the standalone HTML preview and desktop/mobile screenshots, and state the hosting blocker clearly. Never invent a PR or preview URL.
- For this first milestone, match https://www.worldsfinestshows.com/ before proposing a broader redesign: preserve the official ribbon logo, navy/pink/blue palette, multicolour separators, real reference photographs, and homepage section order.
- Suggest visual and usability improvements in small, reviewable steps. Do not silently replace the brand identity.
- Keep demo signup, ticketing, and calendar limitations explicit. Never imply that a local-only form sends email or that this preview sells tickets.
- Use the existing isolated checkout; do not create worktrees unless requested.
- Validate builds and representative interactions at desktop and mobile sizes before delivery.
